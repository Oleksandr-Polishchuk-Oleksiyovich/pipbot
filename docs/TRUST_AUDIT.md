# Аудит промптів і текстів на суперечності з TRUST_MODE (27.10.2026)

Принцип: слова людей про повтори важливіші за CV; число від будь-кого про чуже відео зараховується власнику відео; без підозр, без
«не зараховано» від CV, без лекцій. Джерела перевірено: `prompts.py` (усі промпти й bot_texts), `agents/*`, `app/flow.py`, `docs/SPEC.md`,
а також живу БД VM через diag-секції `prompts_db` / `bot_texts_db` (read-only; `tools/vm_diag.py`).

## Живі дані в БД (VM, 27.10 ~20:10 Kyiv)
- `prompts`: усі ключі `updated_by=seed` і дорівнюють дефолту з коду, КРІМ `coach_dynamic` (v6, `git_migration`, 88 символів:
  «Спеціальні правила тренера (v7): Завжди вітати учасників із завершенням підходу!»). Він м'який → суперечностей у БД-оверрайдах НЕМАЄ.
  Дефолтний `COACH_DYNAMIC_DEFAULT` із коду на проді не діє (рядок у БД не seed), тож його «дискваліфікація/вердикт» — лише код-дефолт для нових БД.
- `bot_texts`: 31 рядок, усі дорівнюють дефолтам з коду (`equals_code_default=true`) → оверрайдів немає.
- Висновок: ідемпотентні ops для правки БД-оверрайдів НЕ потрібні й не застосовувались; `coach_base`/`reps_claim` (seed) оновляться автоматично при деплої.
